# Contract item pagination header: proposed Task 1 amendment

**Status:** Incorporated into Task 1 and independently verified during preparation PR review. The implementation plan controls the final contract; this report preserves the amendment's source reasoning. The existing two tasks remain unstarted. No production edits, dependency changes, network requests, or snapshot regeneration were performed for this report.

**Reason and source contracts:** [The item-fetch plan](../../plans/2026-09-05-ingestion-item-fetch-integrity-plan.md), Task 1 and its upstream-contract paragraph, consumes the optional `200 X-Pages` header and deliberately rejects responses missing it. [ESI dependency registration](../../pitfalls/implementation-pitfalls.md), section 4.C, checklist line 433, requires this dependency in the same PR. [Endpoint declarations](../../../app/backend/tools/esi_spec_monitor/manifest.py), `Endpoint` (line 51) and the item entry (line 104), currently declare only body fields. [Monitor projection and comparison](../../../app/backend/tools/esi_spec_monitor/monitor.py), `_project_endpoint` (line 246), `_diff_field_shape` (line 417), and `_diff_manifest_consistency` (line 485), already supply the shape, consumer attribution, and missing-dependency machinery needed below.

**Projection and comparison contract:**

- Add `Endpoint.consumed_response_headers: dict[str, str]` with an empty default, documented as headers of the `200` response. Register only `X-Pages` on `GET /contracts/public/items/{contract_id}`, attributed to `core/esi_client_class.py ESIClient.get_contract_items / _read_contract_item_page`.
- Project only explicitly declared headers into a separate `response_headers` mapping; omit that mapping for endpoints with no declarations to avoid unrelated snapshot churn. Match HTTP header names case-insensitively and use the canonical subject `response-header:200:x-pages`. Resolve local references on the 200 Response Object, Header Object, and its schema through `_resolve`; preserve its failure behavior for unresolvable references.
- Describe the header schema with the existing type/format/enum/array-shape helpers and record `required` from the upstream Header Object, defaulting to `false`. Never derive requiredness from the client's fail-closed policy. Ignore header prose, unrelated headers, and headers under other response statuses.
- Merge the status-qualified header consumer into the existing `consumers` map. Compute body misses against body fields and header misses against the header projection, then combine them in `consumed_fields_absent_from_spec`, preserving body-field handling. Missing header declarations must receive the existing manifest-consistency checks rather than silently disappearing from the projection.
- Add a `_diff_keyed` pass for `response_headers`, reusing `FIELD_ADDED` / `FIELD_REMOVED`, `_diff_field_shape`, and `removed_severity=None`. Keep the qualified subject in findings and reports. This preserves existing conventions: removal, type/format/enum change, and required-to-optional change are breaking in the pinned view; addition and optional-to-required change are informational. `_Context.add` keeps every newest-view finding informational. Retain the current missing-dependency deduplication and CLI exit behavior.

**Meaningful tests:** Extend [the monitor's fixture tests](../../../app/backend/tools/esi_spec_monitor/tests/test_monitor.py), using real `project`, `build_snapshot`, `compare_snapshots`, and `format_report` calls. Run the new tests red before implementation, then the complete monitor test file green with pristine output.

- Assert an inline optional integer header projects its exact descriptor and consumer; omitted `required` becomes `false`, explicit `true` remains `true`. Equivalent local response/header/schema references produce the same projection; an unresolved consumed-header reference raises. Verify case-only spelling changes and key reordering are quiet.
- Mutate header removal, type, format, enum, and both requiredness directions independently. Assert exact finding kind, status-qualified subject, consumer, and severity in the pinned view; repeat a breaking mutation in only the newest view and in both views to assert informational downgrade and one finding per affected view. Assert rendered output identifies the item caller and header.
- A newly declared but undocumented header produces `MANIFEST_FIELD_UNDOCUMENTED`; ordinary header removal produces only the matching header `FIELD_REMOVED`, with no duplicate manifest finding. Restoring a missing header is informational. Unchanged projections remain quiet. Body fields and request parameters with similar names must not satisfy the header declaration.
- Changing an undeclared 200 header, a 204 `X-Pages` header, or descriptions produces no header finding. Preserve all existing body/status/parameter tests. Assert the real manifest declares only the item endpoint's `X-Pages` dependency, and the regenerated committed snapshot includes its consumer and integer descriptor with `required: false` and no missing declaration in both views.
